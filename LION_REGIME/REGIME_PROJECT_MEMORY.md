## Решения, принятые без Leon'а (сессия 1) — можно отменить

| Решение | Почему | Где |
|---|---|---|
| Сессии привязаны к таймзоне своего рынка (Tokyo / Berlin / London / New York), заданы в его wall-clock | Единственный способ «DST обрабатывать явно» без хардкода. Летом совпадает с таблицей ТЗ 1:1. Зимой NY-сессии по Израилю на час раньше в окна 08–27.03 и 25.10–01.11 — это правильно: NYSE открывается в 09:30 ET, а не в 16:30 IL | `SessionSchedule.DefaultDefinitions` |
| ASIA привязана к Asia/Tokyo | Токио без DST → 23:00–07:00 UTC круглый год; зимой по Израилю 01:00–09:00 | там же |
| Пересечение окон: побеждает сессия с большим `SessionTag` | FRANKFURT > ASIA, NY_PRE > LONDON, LONDON_CLOSE > NY_CASH. Более узкое/позднее окно информативнее. H/L считаются у всех | `SessionTag`, `SessionSchedule.Classify` |
| `IsSessionOpen` / `IsSessionClose` = 15 минут (3 бара M5) | В ТЗ N не задано | `SessionSchedule.DefaultOpenWindowMinutes` |
| Бар классифицируется по времени открытия | Стандарт cTrader; бар [10:00, 10:05) принадлежит сессии, содержащей 10:00 | `SessionSchedule.Classify` |
| Выходные = Sat/Sun по локальной дате якоря → DEAD | ASIA понедельника (Tokyo Mon 08:00 = Sun 23:00 UTC) не выходной; суббота Tokyo = пятница 23:00 UTC → DEAD. FX-открытие воскресенья 22:00 UTC до 23:00 → DEAD | `SessionDefinition.WindowFor` |
| Gold: ASIA → тег DEAD, но Asia H/L копится | Asia range нужен детектору и карте ликвидности | `SessionProfile.Gold` |
| Core = net6.0, тесты = net8.0 | net6.0 — target cBot-проектов cTrader; тесты гоняем на SDK 8 | csproj |
| **Слой 2:** единица расстояния и глубины свипа — ATR(14) на **H1** | В ТЗ не сказано, какой ATR. M5-ATR даёт бессмысленно большие числа до дневных пулов, H1 — привычный масштаб (PDH обычно 1–5 ATR). Тот же ATR, что у детектора режима | `LiquidityMap.DistanceAtr` |
| Допуск равных хаёв считается по ATR **своего** ТФ (H1 для H1-свингов, H4 для H4) | Кластер на H4 должен мериться масштабом H4 | `TryBuildEqualPool` |
| Цена EQ-пула = экстремум кластера (max для хаёв, min для лоёв) | Стопы стоят за крайним уровнем кластера, а не за средним | там же |
| Окно возврата = бар свипа (бар 0) + 6 баров M5 | Согласовано с условием DISTRIBUTION в ТЗ («последние N = 6 баров M5»). WICK-свип разрешается сразу на баре 0 | `ReclaimWithinBars` |
| `MaxDistanceAtr` = 10 | В ТЗ значение не задано | `LiquidityMapSettings` |
| `EqLookbackSwings` = 20, `PoolRetentionDays` = 90 | В ТЗ не заданы. Retention 90 дней, чтобы PMH/PML доживали до использования | там же |
| Сессионные пулы только для ASIA, LONDON, NY_CASH | Ровно то, что перечислено в ТЗ. FRANKFURT/NY_PRE/LONDON_CLOSE/NY_CLOSE — в PARKING_LOT | `SessionPoolType` |
| Пул создаётся в момент завершения сессии и может быть снят тем же баром | Азия кончилась в 07:00, лондонский бар 07:00–07:05 снимает её хай — это причинно корректно, не lookahead | `HarvestSessionPools` |
| Равные хаи не считаются фрактальным свингом (строгое `>` с обеих сторон) | Ровные вершины обрабатывает EQH/EQL, дублировать их свингами не нужно | `SwingDetector` |

**Найдено при написании тестов (мои ошибки в ожиданиях, код был прав):**
- Один бар может снять два уровня с РАЗНЫМ типом свипа: закрытие 120 при уровнях 110 и 130 даёт
  BODY для 110 и WICK для 130. Это правильно и теперь зафиксировано тестом.
- ASIA и FRANKFURT в летнее время заканчиваются одновременно в 07:00 UTC — разделить их окном нельзя.

**Сломано / ограничения:**
- **`sweep_reclaimed` нельзя писать в CSV на баре свипа.** Возврат известен только через 6 баров.
  Таггер обязан писать эту колонку вторым проходом или буферизовать 7 баров, иначе получится lookahead.
  Это главный риск при написании слоя таггера.
- `GetTargets` линейно сканирует все пулы. На 6 месяцах × 4 инструмента это приемлемо (прогон 6 месяцев
  в тесте занимает ~1 секунду), но при росте объёма понадобится индекс — записано в PARKING_LOT.
- Пулы не «обновляются»: новый день создаёт новый PDH-пул, старый остаётся в списке как несобранный.
  Это осознанно: старый PDH — по-прежнему ликвидность. Retention 90 дней ограничивает рост.
